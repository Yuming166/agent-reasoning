# 今晚的多 Agent AutoResearch：时序图候选检索与未来知情教师蒸馏

**执行说明｜2026-09-30｜供服务器 Codex 从 GitHub 读取后执行**

本文件是一次有明确产物和停止条件的研究任务，而不是实验已经完成的报告。服务器项目目录为 `/storage/gaoym/ex-graph-microtransaction-analysis`。开始时先核对实际数据、代码、可用模型和机器状态；本文列出的既有数字是探索性锚点，不能当作新实验结果。

## 0. 任务目标与研究问题

在钱包 `w` 的时刻 `t`，系统只观察 `t` 前的链上事件。目标是预测未来 7 天内：(A) 钱包是否发起一笔符合定义的外部交易；(B) 若会交易，第一笔交易的 `to` 目标地址是否能进入按置信度排序的 5 个地址。候选检索、Top-5 排序和活动判断须分别评估。

本轮要探索的 NLP 方法是：**训练时**让教师 LLM 同时看到截止前历史和真实后续动作，提出“哪些历史模式与这个结果相容”的多条、带证据的可执行假说；独立程序验证它们，再将有效假说作为软监督。**推断时**学生只能看到截止前历史，预测活动、假说/因子和候选地址分数。教师的回溯解释不是实际心理动机，也不是因果标签。主研究假说是：这种经验证的结构化解释蒸馏，是否在相同历史、候选池和计算预算下，改善活动预测或 Top-5 排序，尤其是在图检索困难的分层。

本轮必须产出真实的候选检索试验、教师标注小样本、学生训练和公平对照；不能以初始化目录、写计划或一次成功的模型调用冒充研究完成。若某环节受数据或时间限制，交付已完成的实验和可复算的阻塞证据。

## 1. 已冻结语义与现状边界

以仓库 [`notes/next-transaction-top5-protocol-v2.md`](./next-transaction-top5-protocol-v2.md) 为**当前任务与方法协议**；v1 是历史版本。v2 保留活动/第一目标 Top-5 的标签和指标分母，明确加入训练期未来知情教师、LLM 因子发现与学生蒸馏。若发现标签缺陷，继续升版本并记录差异，不能悄悄改动分母。

- 一个 case 是 `(wallet, cutoff_utc)`。输入事件和图边时间必须**严格早于** `t`；标签窗是 `[t, t+7 days)`，不同评测 cutoff 的标签窗不重叠。
- 未来 eligible transaction 是钱包发出的 `external_tx`，`to` 地址非空；合约调用和零 ETH 金额交易在范围内。失败交易是否纳入，须先审计并冻结。
- `y_active` 指未来窗内是否至少有一笔 eligible transaction。`y_dest` 是首笔的 `to` 地址；先后顺序须使用区块号、交易索引等规范键，不可依赖文件顺序。`y_dest` 只在 `y_active=1` 时定义。
- 主任务不预测买卖、人的意图或收益，也不把 token transfer/internal trace 当作另一次未来外部交易。它们可以作为截止前的历史特征。
- 当前离线事件库据既有报告覆盖 2022-03 至 2022-08，候选检索 bootstrap 位于 `artifacts/candidate_autoresearch_20260930_20260929T174636Z/`。先核对文件和 SHA-256，再决定本轮可用的 cutoff；没有足够后续 7 天数据的 cutoff 不进入评测。
- 已看过的 240 钱包及 June/July/August 结果是探索数据，不能重新命名为盲测。此前 full-panel 候选覆盖和图检索结果也只作诊断；bootstrap `exit_code=0` 仅证明初始化成功，**不代表 autoresearch 已运行**。
- 不把 X、ENS 或 influencer 文本接入本轮主任务；当前没有足够可靠的历史身份链接。这一轮先把纯链上任务与方法验证做好。

## 2. 今晚要回答的四个可证伪问题

1. **候选覆盖：**在严格 as-of 的完整可见地址空间中，时间图检索和因子门控能否比 own-recency、频次、全网热门度及混合基线，提高 `Recall@5/50/500/2000`？新增命中来自哪些旧/新目标分层，代价是多少？
2. **教师可靠性：**教师在知道未来结果后提出的假说，有多少能够通过独立的时间、证据、typed rule、certificate 和反事实验证？不要求硬选唯一“真正原因”；允许多标签与 `UNKNOWN`。
3. **学生效用：**学生在完全看不到未来和教师解释的 dev/holdout 推断中，加入经验证伪标签是否优于相同架构的无教师版本、打乱教师标签版本和仅数值/图特征版本？增益能否超出候选支持率本身？
4. **解释与预测的联系：**学生预测的因子是否与它实际提高分数的候选地址的图证据一致？删除关键历史证据后，因子与候选分数是否发生合理变化？这只是受控输入敏感性，不宣称现实因果。

## 3. 多 Agent 分工与共享契约

优先使用服务器 Codex 当前任务可用的多 Agent 协作能力。由**协调 Agent**统一冻结协议、分配文件所有权、汇总试验、决定是否进入 holdout。扩展为七个**职责**，但不要盲目开七个同时运行的 Agent：先让协调者与最多三个独立子任务并行，核实实际并发上限、GPU/模型服务吞吐及文件冲突后再扩容。后续角色可复用已有 Agent，或分批启动；记录实际并发数、失败/重试和 token/计算成本。若环境不能同时运行多个 Agent，就按同一责任边界顺序执行，不伪称多 Agent 已运行。所有长任务使用服务器上可恢复的普通进程/`tmux` 与检查点；不要用曾在该服务器因 `bwrap: Operation not permitted` 失败的 Codex CLI 后台代理。

| 角色 | 独立责任 | 必交产物 | 不可做的事 |
| --- | --- | --- | --- |
| 协调 Agent | 锁定 run ID、共享接口、预算、指标与合并顺序；只在方法冻结后解锁 holdout | `manifest.json`、交接记录、最终 `REPORT.md` | 根据 holdout 改规则或掩盖失败 trial |
| 数据与泄漏审计 Agent | 构造 case/split、审计事件 schema 和 as-of 边界 | split 表、标签核对、`asof_audit.json` | 用未来活跃集合筛钱包或图节点 |
| 基线检索 Agent | own-recency、频次、全网热门度及混合；建立统一候选接口 | B0 case 级候选、覆盖与成本 | 更改标签或主评测器 |
| 时间图检索 Agent | 时间二跳、hub 抑制、typed meta-path 与轻量因子门控 | G1–G3 候选、路径 witness、消融 | 将真实未来目标注入候选池 |
| 因子发现与教师 Agent | 在 train-discovery 用 LLM 提议组合因子；在 train-labeling 做回溯多标签标注 | 原始响应、因子提案、伪标签 | 把回溯解释称为真因，或把未来地址写死进因子 |
| 编译与反事实验证 Agent | 独立实现 AST 编译、历史证据/证书重算、证据删除试验 | 冻结因子目录、验证结果、失败分类 | 让教师声明自己的提案已验证 |
| 学生与独立评估 Agent | 训练活动头、因子头和 Top-5 排序器；运行公平消融与盲测 | 模型配置、case 级预测、比较表 | 在 dev/test 推断读取未来标签或教师回溯文本 |

第一波并行做数据审计、B0 基线和图检索接口；第二波在冻结接口后做因子发现、独立验证和学生实现；第三波由协调者统一评估。教师与验证器必须独立，学生可以先写架构但须等冻结的伪标签进入训练。各 Agent 拥有不同脚本和运行子目录；共享的 case ID、事件 schema、cutoff、候选接口由协调 Agent 先冻结。采用短的交接文件记录“输入、输出、校验和、已知问题”，不要靠聊天记忆传递关键状态。审计 Agent 可否决有泄漏的试验，不能把它计入有效比较。

### 模型路由与凭据边界

用户允许使用自备模型服务，也允许在其可用时调用 `gpt-6-astra`；服务器本地 `Qwen3.5` 可作后备和批量处理。**当前尚未验证第三方网关确实提供该模型、其计费方式或服务稳定性。** 在私有服务器环境中配置新的有效令牌；只通过环境变量或受限权限的私有配置读取，绝不把令牌、Authorization header、完整配置或含凭据的请求日志提交 Git。用户曾在对话中贴出令牌，应换发后再用于长期作业。项目文档只记录 provider 别名、模型 ID、版本、响应 ID、用量和失败原因，不记录密钥。

若用 Codex 的自定义 provider，按 [官方配置参考](https://developers.openai.com/codex/config-reference) 在服务器私有配置中使用 `env_key`，不要使用明文 `experimental_bearer_token`。示意如下；实际 base URL、令牌和网关特有 header 由服务器私有配置提供，不能提交：

```toml
model_provider = "research_gateway"
model = "gpt-6-astra"
[model_providers.research_gateway]
name = "Research gateway"
base_url = "<gateway base URL from private configuration>"
wire_api = "responses"
requires_openai_auth = false

```

此示例只说明字段边界，不证明第三方网关兼容 Codex 工具调用或确实提供 Astra。先在隔离运行配置中做 smoke test，不改坏服务器现有可用配置。若通过 Python/Responses 客户端调用教师，采用同样的环境变量与日志脱敏规则。

启动时用不含链上原始数据的极小请求验证网关的 `/responses` 兼容性、`gpt-6-astra` 的实际返回模型、结构化输出、错误率与用量字段。验证通过后，优先把 Astra 用于高价值的因子提议、难例裁决和研究审稿；不要默认把全部训练样本交给昂贵模型。用同一批分层 train pilot 比较 Astra 与 Qwen 的可编译率、证据合法率、因子多样性、响应时间和实际费用，再决定批量教师路由。若网关不可用或费用不可确认，使用本地 Qwen 并完整报告模型质量边界。模型服务的并发请求数按实际限流/GPU 吞吐调节，与 Agent 人数分开控制。

### AutoResearch 框架选择

采用 [Karpathy AutoResearch 的 `program.md` 思路](https://github.com/karpathy/autoresearch/blob/master/program.md)：固定数据与评测器、限定可修改的方法文件、每个 trial 只检验一个有记录的改动、失败也记录并可恢复。原仓库面向单 GPU 语言模型训练，**不直接搬用**它的训练代码或无限循环；本项目需要多目标、时间切分和严格候选分母，故以本文件和冻结评测器构建轻量定制循环。搜索结束时间、单 trial 超时和资源配额都须写入 manifest。

第一晚用 `program.md + trial_log.jsonl + 不可覆盖产物目录 + 可恢复后台进程` 即可。基线跑通后，可用 [Optuna 的持久化 study](https://optuna.readthedocs.io/en/stable/tutorial/20_recipes/001_rdb.html) 搜索 G3 门控和学生超参数；Optuna 只选参数，不代替 Agent 提出新图因子。若服务器已装 [MLflow Tracking](https://mlflow.org/docs/latest/ml/tracking)，可同步记录运行；今晚不因安装新追踪平台延误实验。任何实验管理工具都不得改写已冻结的评测器或借 dev 多次窥探 holdout。

## 4. 数据切分与防泄漏门槛（最先完成）

1. 从**完整离线事件**核对事件类型、地址规范化、外部交易发送方/接收方、失败状态和排序键，生成 wallet-cutoff/标签表。未来地址只作标签，不能出现在构造截止前可见图的代码路径。
2. 排除已被反复观察的 240 个探索钱包，再从其余钱包构造钱包隔离 train/dev/holdout；train 内再分 discovery 与 labeling/fit。入样条件只根据相应 cutoff 前历史；记录未达入样条件和 7 天未来不完整的数量。若无法获得真正更晚且完整的时间窗，分别报告钱包隔离结果和时间外推不可用，不能伪造“更晚 holdout”。
3. 固定各 split 的 case ID、cutoff、标签、地址库版本、输入哈希与随机种子。train 可以给教师看未来；dev 的未来只供指标和开发选择；holdout 标签在方法冻结前不得进入 prompt、模型、网格或人工调参视野。
4. 每个特征、图边、全网统计量和合约元数据都要通过 as-of 检查：`event_time < t`。禁止用“全量文件中的活跃地址集合”预筛历史图。使用严格大于等于 `t` 的未来事件时只能生成标签。
5. 输出可机器复核的 `asof_audit`：未来边混入数、future-derived 地址过滤数、标签窗重叠数、跨 split 钱包重叠数、缺失规范排序键数。任何关键项非零，停止后续模型比较并修复。

## 5. 候选检索 AutoResearch

候选器返回按分数排序且互不重复的截止前可见地址和其来源因子；真实目标若在截止前全网从未出现，主指标仍计失败。先实现可复算的强基线，再试复杂方法：

1. **B0：**钱包最近交互、交互频次、全网历史热门度、其简单混合；不足 `K` 以冻结的全网历史规则补足。
2. **G1：**时间衰减两跳图分数、common neighbors/Adamic–Adar，抑制高连接 hub；给出路径 witness 和边时间。
3. **G2：**typed meta-path（external transaction、token transfer、internal trace 分开处理），不同路径类型各有分数与来源，不把同一交易的多条衍生边当独立证据。
4. **G3：**因子或轻量学习门控：以截止前的钱包活跃度、重复率、新目标率、两跳覆盖、hub 比例、局部图变化等选择/加权检索器。门控在 train 拟合、dev 选参；比较同预算固定混合。
5. 时间若允许，再试个性化 PageRank/图嵌入；必须报告构图和查询成本。不得因为复杂就省略 B0/G1/G2，也不能把外部未来活跃的节点集当候选空间。

采用**确定性、预算受限的试验循环**：每 trial 只改变一个有记录的方法因素；先跑小样本合法性与速度，再跑完整 dev；记录配置、代码提交、数据哈希、seed、wall time、内存、`Recall@5/50/500/2000`、地址库可见上界、候选来源分层。以准确覆盖和成本共同筛选 1–2 个候选器，冻结后供所有排序方法共享。**Recall@K 是候选支持率，不是预测准确率**；必须另报最终 Top-5。

## 6. 未来知情教师：回溯解释不是因果真值

因子有两层来源：研究者先冻结**可执行原子语法**（计数、最近出现、唯一对手方、两跳路径、共同合约、时间趋势等操作及合法参数）；LLM 在 train-discovery **提出这些原子的组合因子**，而不是只从八个手写名称中选择。区分钱包级活动因子 `F_wallet(H_<t)` 和候选级关系因子 `F_pair(H_<t,candidate)`。提案必须是参数化 typed expression，不能包含某个未来目标地址常量或为单个钱包量身定做的规则；训练时可用 `candidate=y_dest` 检查已发生目标，但推断时必须对历史检索的每个候选运行同一表达式。程序把提案编译为规范化 AST，检查截止前 witness、支持数、复杂度，合并同义因子；在独立 train-labeling 子集上检查稳定性后冻结目录。提案失败也要保存。完整流程与信息边界见 [v2 协议](./next-transaction-top5-protocol-v2.md)。

随后仅在 train cases 上调用回溯教师 LLM 做多标签标注。提示输入分为不可混淆的两个区域：

```text
HISTORY: 仅含 event_time < t 的带稳定 evidence_id 事件摘要与图路径。
OBSERVED OUTCOME: [t,t+7d) 内是否有 eligible transaction；若有，首笔 to 地址。
TASK: 从已冻结、由 LLM 提议且程序验证的 typed 因子目录中选择 0..N 条
      与结果相容的历史假说，引用截止前 witness IDs，给出因子参数、
      预期状态和不确定性；证据不足时 UNKNOWN。
```

`repeat_target`、`recent_neighbor`、`two_hop_path`、`shared_protocol_or_contract`、`global_popularity`、`activity_rhythm`、`recent_dormancy`、`unsupported_new_target` 只是种子示例，不是最终封闭清单。新颖性可以来自 LLM 提议可泛化的组合因子，但所有因子最终都必须可执行、可重算。因子是**预测性模式**，不是投资者的真实心理原因。教师可以选择多个相容模式；对未来不活跃 case，不能凭空描述下一目标。

独立验证器读取完整截止前窗口，而非仅凭教师摘要，检查：JSON/schema、typed factor/rule 匹配、witness ID 真实性和时间、规则可执行性、certificate 重算、目标与历史路径的对应关系。对至少一部分已验证假说执行删除关键边、删除最近事件、遮蔽最近窗口等反事实修改并**重新执行**规则；报告 `CHANGE / INVARIANT / WITHDRAW`。若要测“模型反事实修订能力”，必须再次让模型读取修改后历史并作答，不能将执行器状态冒充模型修订。

保存每次原始请求/响应、模型名称和版本、prompt 哈希、token/延迟、失败原因。伪标签仅从验证通过的 train 项目提取，多标签或概率权重可用；未验证/不支持的项目为缺失或 `UNKNOWN`，不得作为负样本硬灌。先做有限教师样本 pilot；若有效覆盖很低或标签高度同质，就报告该结果，不扩大无效调用。

## 7. 学生模型与公平对照

学生推断函数明确为 `f(H_t, G_<t) -> (p_active, factor_scores, retrieval_weights, top5_destinations)`。模型输入不得包括未来标签、未来目标、教师回溯解释或其 embedding。可以用数值/时序特征、图因子和截止前的结构化事件文本。先选小而可稳定训练的架构：共享编码器 + 活动头 + 因子辅助头 + 检索门控/候选排序头。所有学生 arm 先共享同一个截止前生成的候选**超集**；门控只在这个超集内调权/排序。若研究不同检索预算或候选组成，作为单独的检索实验比较。若因子伪标签稀疏，使用带 mask 的辅助损失；总损失结构为 `L_activity + λ L_rank + μ L_factor`，权重只在 dev 冻结。`L_rank` 在 train 的真实目标不在候选池时跳过该样本的排序损失，不得偷偷注入目标；这类样本单列 out-of-support 诊断，主评测照样计失败。

至少比较以下**同一训练 case、同一候选池、同一特征预算**的 arm：

| arm | 目的 |
| --- | --- |
| 数值/图基线 + 固定候选器 | 检验任务难度与候选瓶颈 |
| 同架构学生、无教师因子损失 | 隔离模型容量收益 |
| 学生 + 原始未验证教师标签 | 检验验证器的贡献（仅作受控消融） |
| 学生 + 已验证教师伪标签 | 主方法 |
| 学生 + 在 train 内打乱的教师标签 | 检查额外训练信号/容量假象 |
| 学生 + 固定检索混合 | 检查学习门控的贡献 |

教师可作为仅训练时的上界诊断，但不能在 dev/holdout 推断看到未来。活动任务在全部 cases 上报 AUPRC、Brier、AUROC、固定 dev 阈值下 balanced accuracy；目标任务在**全部 active cases** 上报 `Recall@5`、`MRR@5`，包括候选未命中；同时报告联合成功率、候选 `Recall@K`、按旧/新目标和活跃度分层、配对置信区间，以及训练/推断成本。若一个 arm 有缺失预测，须以预先冻结的 fallback 补全并计入原分母。

## 8. 今晚的运行顺序、检查点和停止规则

**阶段 1：数据与 split。** 做 schema/标签/as-of 审计，排除探索钱包，冻结 train/dev/holdout case ID。未通过则只修数据，不调用教师。

**阶段 2：检索。** B0、G1、G2、G3 至少各完成一个真实 dev trial，保存 case 级候选与指标；复杂方法失败也留原始错误和所耗时间。先冻结候选器，再开始主要排序比较。

**阶段 3：因子发现与教师。** 在 train-discovery 小样本上让 LLM 提议组合因子，编译、去重、独立验证并在 train-labeling 子集检查稳定性；冻结因子目录。然后在分层 train 样本上运行未来知情教师与验证器，报告提案数、可编译率、目录规模、伪标签覆盖、各因子频率和反事实执行结果。教师输出可缓存并断点续跑；模型服务故障时不要丢失已完成响应。

**阶段 4：学生。** 跑无教师、验证教师、打乱教师三个最小对照；若时间足够，再补未验证教师和门控消融。所有 arm 使用相同 split 和候选池。对 dev 做误差分析，确定超参数后将方法与代码哈希写入 `freeze.json`。

**阶段 5：holdout。** 仅当审计通过、方法/阈值冻结且有真正未观察的 holdout 时运行一次主要比较。若达不到条件，保持锁定并如实报告 dev 结果。不得为了“今晚完成”打开 holdout 调参。

协调 Agent 每完成一个阶段就写 checkpoint，失败从最近 checkpoint 恢复。服务器 SSH/本地屏幕断开不应中止普通后台作业；必须实际检查进程、日志更新时间和产物，不能只凭聊天或 `tmux` 名称声称工作在运行。任务截至北京时间 **2026-09-30 08:00** 时先停止新试验、汇总已有结果；若读到本文时已过该时间，改为一次最多六小时的有界运行，并在 manifest 写实际开始/结束时间。不要自动无限循环。

不发起新的付费 BigQuery 查询；优先只用现有离线数据。若离线数据确有关键缺口，先在报告中列出所需查询、dry-run 估价和计费上限，不能擅自执行。无需新增社交抓取。用户已允许调用自备 LLM 网关和本地 Qwen；外部网关先做最小兼容性与质量 pilot，并记录调用数、token 和已知费用。若无法确认计费，停止批量外部调用，转用本地 Qwen；不把“有 API key”解释为无限费用授权。并行数量须受 GPU 显存、网关限流和服务稳定性约束。

## 9. 必交目录与验收标准

在服务器项目 `artifacts/` 下创建一次性、不覆盖的 `candidate_teacher_student_autoresearch_<UTC_RUN_ID>/`，至少包含：

```text
manifest.json                 # 输入哈希、代码版本、模型、seed、时间与预算
program.md                    # 本轮冻结的试验规则/变更记录
splits/                       # case ID、标签口径、钱包隔离审计
retrieval/                    # case 级候选、来源证据、trial 日志与覆盖/成本
teacher/                      # 因子 AST/目录、原始响应、验证结果、伪标签与反事实执行
student/                      # arm 配置、checkpoint、case 级预测和指标
freeze.json                   # 若解锁 holdout，记录冻结方法与哈希
asof_audit.json               # 数据与图的时间有效性检查
REPORT.md                     # 已完成项、实际数字、失败项、下一步
run.log / exit_code           # 可恢复运行和最终状态
```

`REPORT.md` 首屏必须写**状态矩阵**：每个阶段是“计划/正在运行/已完成/失败”，对应实际文件、case 数和退出状态。随后给出统一分母表、最佳方法与所有对照、成本、95% 配对区间、至少五个成功/失败 case 的证据链，以及哪些结论只能作为 pilot。若试验结果不支持主假说，明确写出，保留负结果。论文层面的贡献只有在独立测试与必要消融支持后才能陈述。
